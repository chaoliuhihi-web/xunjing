# 寻境业务对象与状态机文档 v1.2

- 文档日期：2026-08-31
- 文档性质：产品业务模型与服务端状态流转配套文档
- 对应产品文档：[寻境 C 端产品功能文档 v1.4](./寻境C端产品功能文档_v1.4.md)
- 对应技术蓝图：[寻境 C 端完整产品技术实施蓝图 v1.0](../02_开发规划/寻境C端完整产品技术实施蓝图_v1.0.md)
- 适用范围：C 端旅程、同行共同记录、作品、订单与履约

## 1. 文档边界

本文维护寻境的业务对象、对象关系、权限边界和状态机。用户功能、页面入口、P0/P1/P2 和验收标准以产品功能文档为准。

核心原则：

1. 所有功能围绕同一个 `Trip` 聚合，但旅程、轨迹、作品和订单使用独立状态机。
2. `PlannedDay/PlannedLeg` 表示计划，`ActualVisit` 表示行后重建的实际到访，`TrackSession` 只是可选证据，两者不得相互覆盖。
3. 同行人以查看和共同记录为主，不建立投票或正式确认对象。
4. 每条素材、可选轨迹、可选“记下这里”、修改和制品都保留贡献者、来源、时间和版本。
5. 删除、退款、重印和回退使用独立记录，不覆盖历史事实。
6. 合作方、渠道归因、佣金和结算对象暂不进入当前业务模型；未来启动合作方产品时另行补充，不预埋当前状态流转。

## 2. 旅程与成员对象

### 2.1 `Trip`

一次真实旅行的聚合根，保存：

- 创建者、目的地、日期、主题和封面。
- 当前计划版本和当前旅程状态。
- 成员、来源、计划、实际记录、作品和订单引用。
- 隐私范围和删除状态。

### 2.2 `TripMember`

表示旅程创建者和已加入的同行成员：

- `OWNER`：修改计划、邀请或移除成员、管理整趟旅程、定稿、下单和删除。
- `MEMBER`：查看完整行程，按需“记下这里”，上传照片、视频、语音和备注，管理自己的素材。
- `VIEWER`：仅通过分享链接查看允许公开的计划，不进入成员列表。

不设置投票权、正式确认状态或“全员确认后才能出发”的流程。

### 2.3 `TripInvite`

同行邀请和查看链接：

- 区分仅查看链接与加入旅程邀请。
- 记录创建人、有效期、可见范围、使用次数和撤销时间。
- 接受加入邀请后创建 `TripMember`。

## 3. 攻略来源与计划对象

### 3.1 `PlanSource`

用户主动提供的计划来源：

- 第三方平台链接。
- 粘贴的攻略文字或地点清单。
- 攻略截图、订单截图或票据。
- 用户手工创建的空白计划。

链接来源至少记录：

- 原始 URL、来源平台和内容类型。
- 获取方式、获取时间和最近核验时间。
- 页面标题、作者或发布者等允许保存的来源信息。
- 提取出的地点、日期、交通、住宿、餐饮和注意事项。
- 获取失败原因、待补充字段和用户修正结果。

不把第三方完整正文、图片和评论复制成寻境内容资产；不绕过登录、访问控制或反抓取机制。

### 3.2 `SourceFetchJob`

第三方链接获取与解析任务，关联 `PlanSource`，保存平台适配器、重试次数、解析版本、结果摘要和错误。

### 3.3 计划对象

- `PlannedDay`：计划中的某一天。
- `PlannedWaypoint`：当天地点、顺序、预计到达和停留时间、必去或可选标记。
- `PlannedLeg`：两个计划地点之间的交通方式、预计距离、时间和路线显示信息。
- `PlanVersion`：用户每次保存后的计划快照，支持预演复现和变更追踪。

同行查看的是当前有效 `PlanVersion`，不产生投票或确认记录。

## 4. 真实旅程与共同记录对象

- `TrackSession`：某位成员主动开启的可选完整足迹；缺失或中断不得阻断行后作品。
- `TrackPoint`：坐标、时间、精度、速度、来源成员和同步状态。
- `ActualVisit`：系统推断或用户确认的实际到访地点。
- `ActualStay`：实际停留区间和时长。
- `CheckIn`：成员可选创建的“记下这里”事件，不要求逐站打卡。
- `MediaAsset`：用户一次选择并上传的原始照片、视频、语音、票根和截图，保存贡献者、拍摄时间、EXIF、位置和删除状态。
- `MediaDerivative`：服务端由原始素材生成的内部缩略图、预览图和印刷中间制品，不是用户需要再次上传的素材类型。
- `TripNote`：成员提交的一句话、语音转写或补充说明。
- `MemoryEvent`：照片、计划、可选轨迹、“记下这里”和备注合并后的叙事事件，保留证据引用和置信度。

共同记录要求：

- 所有贡献内容必须带 `contributorMemberId`。
- 成员可以删除自己的素材；旅程创建者删除整趟旅程时进入统一删除流程。
- 多名成员记录的轨迹分别存储，行后可按时间和地点合并展示，不拼接成伪造的单人轨迹。
- 分享作品默认隐藏精确坐标、住址、酒店和敏感地点。

## 5. 作品、订单与履约对象

### 5.1 作品

- `StoryProject`：旅行故事、电影和旅行书共享的内容工程。
- `MovieVersion`：计划电影或真实回忆电影的版本和制品。
- `BookVersion`：旅行书首版、修改版、校样版和印刷版。
- `Artifact`：视频、SVG、PDF、预览图、Manifest 和 QA 报告。
- `RevisionRequest`：用户自然语言修改、影响范围、结果版本和回退关系。
- `QualityCheck`：事实、图片、版面、PDF、地图、隐私和印刷安全的自动质检结果。
- `ExceptionReviewCase`：只在自动质检失败、高风险内容、关键事实歧义、投诉或人工精修增值服务中创建的例外审核单。

### 5.2 订单与履约

- `Order`：商品、应付金额、实付金额、收货人和当前订单状态。
- `PaymentRecord`：支付、退款和支付渠道流水。
- `PrintJob`：印刷供应商、校样、生产状态和异常。
- `Shipment`：物流公司、单号、发货和签收。
- `AfterSaleCase`：退款、重印、补发和责任判断。

## 6. 独立状态机

### 6.1 `Trip`

```text
DRAFT 草稿
  -> UPCOMING 待出发
  -> ON_TRIP 旅行中
  -> COMPLETED 已结束
  -> ARCHIVED 已归档
```

行后直接做作品时允许 `DRAFT -> COMPLETED`，不要求补造行前和行中状态。不存在“同行已确认”状态；取消和删除作为独立事件记录。

### 6.2 `SourceFetchJob`

```text
PENDING 待获取
  -> FETCHING 获取中
  -> PARSED 已解析
```

异常出口：`NEEDS_INPUT` 需要用户补文字或截图、`FAILED` 获取失败、`BLOCKED` 平台不允许或无法合法访问。

### 6.3 `TrackSession`

```text
RECORDING 记录中
  -> PAUSED 已暂停
  -> RECORDING 继续记录
  -> FINISHED 已结束
```

用户放弃时进入 `DISCARDED`，不计入有效轨迹。

### 6.4 `StoryProject`

```text
COLLECTING 素材收集中
  -> READY_TO_GENERATE 可生成
  -> GENERATING 生成中
  -> AUTO_QA 自动质检中
  -> READY 已完成
```

异常出口：`NEEDS_USER_INPUT` 仅处理高影响问题、`NEEDS_EXCEPTION_REVIEW` 进入例外审核、`FAILED` 生成失败。

### 6.5 `MovieVersion`

```text
QUEUED 排队中
  -> RENDERING 渲染中
  -> REVIEW_READY 可预览
  -> PUBLISHED 已导出
```

计划电影与回忆电影使用不同 `movieType`，不得通过状态互相转换。

### 6.6 `BookVersion`

```text
GENERATING 生成中
  -> AUTO_QA 自动质检中
  -> PREVIEW_READY 首版可翻阅
  -> EDITING 修改中
  -> PROOF_READY 印刷校样可确认
  -> APPROVED 用户已确认
  -> PRINT_READY 可印刷
```

每次修改生成新版本，旧版本可下载和回退。

### 6.7 `Order`

```text
CREATED 已创建
  -> PAID 已付款
  -> PRINTING 印刷中
  -> SHIPPED 已发货
  -> DELIVERED 已签收
  -> CLOSED 已完成
```

退款、售后、重印和补发使用 `PaymentRecord`、`AfterSaleCase` 和新的 `PrintJob` 表达，不覆盖原交付记录。

## 7. 关键跨对象规则

1. 用户保存第一版计划后，`Trip` 可从 `DRAFT` 进入 `UPCOMING`，不等待同行确认。
2. 到达旅行日期、用户打开当日行程或创建者主动开始旅行后，`Trip` 可进入 `ON_TRIP`；不要求先创建轨迹或打卡。
3. 旅行结束后，以计划、一次上传的原始素材和可选轨迹/共同记录生成计划与实际对照，不改写原计划版本。
4. 原始素材只由用户选择并上传一次；`MediaDerivative` 由服务端自动生成、重建和删除，不产生用户补传状态。
5. `StoryProject` 和 `BookVersion` 默认经过自动质检；只有 `QualityCheck` 失败或命中高风险规则时创建 `ExceptionReviewCase`。
6. 用户看到可完整翻阅的保护性首版后可以创建订单并一次付款；修改和印刷校样属于 `BookVersion`，支付属于 `Order`。
7. 用户确认印刷校样且订单已付款后，才允许创建正式 `PrintJob`。

## 8. 审计与删除

- 对象状态变化记录操作者、时间、来源端和前后值。
- 第三方链接保留来源和获取日志，但不长期保留无必要的第三方完整页面副本。
- 用户删除旅程时生成删除任务，覆盖对象存储原始素材、内部派生制品、缓存和备份保留策略。
- 法律、支付和税务必须保留的记录与用户内容分开处理，并在隐私政策中说明。
