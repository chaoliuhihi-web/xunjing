## 5. 新文件放置规则

- 产品“做什么”：`01_产品规划/`
- 工程“怎么做”：`02_开发规划/`
- AI“按什么顺序做”：`04_AI交接任务书/`
- “如何证明做完”：`05_验收与证据/`，实际证据放 `qa/`
- 临时分析、截图、日志和中间产物：`workbench/`、`tmp/` 或 `qa/`，不得放仓库根目录

版本文档使用 `主题_v主版本.次版本.md`。每个主题只允许一份文件标记为 CURRENT；新版本发布后必须同步更新本入口、上游引用和 AI 任务书。

## 6. AI 接手硬规则

1. 先执行只读预检，确认分支、远端、工作树和当前权威文档。
2. 当前工作树很脏时，不得重置、覆盖或顺带提交其他人的修改。
3. 每次只领取一个没有重叠写路径的任务 ID。
4. 先复用现有 UniApp、Yudao、Memory Book Worker 和门禁，将 Worker 演进为 Codex Harness + pinned `travel-memory-book` Skill 的生产 Runner，不创建平行技术栈。
5. 没有真实上传、持久化、生成、付款或履约证据时，必须标记 `BLOCKED` 或 `NOT_READY`，不得以 mock 成功态代替。
6. 完成任务后提交代码、测试、证据索引和 handoff；正式推送同时同步 GitHub 与 Gitee。
