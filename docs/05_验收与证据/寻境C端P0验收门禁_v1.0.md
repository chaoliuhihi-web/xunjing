- 执行依据：[寻境 C 端完整产品 AI 实施任务书 v1.0](../04_AI交接任务书/寻境C端完整产品AI实施任务书_v1.0.md)

## 1. 总原则

寻境只有在文档、代码、接口、真实运行、真实用户操作、支付履约和业务指标形成证据链后，才可称为完整 C 端可试运营产品。

以下内容单独存在时均不算完成：

- Figma、截图、静态 HTML、动画视频或 PPT。
- localStorage 作品、固定 JSON、定时器进度或前端成功文案。
- 只有 Controller/表结构但没有运行中的 API。
- 只有 Worker 本地 PDF，没有用户上传和任务恢复。
- 支付按钮跳转、沙箱回调或手工改库伪装真实付款。
- 印刷报价、物流单模板或合作意向伪装真实签收。
- 内容平台排期、播放、点赞或咨询伪装产品付费。

每一级门禁失败，后一级不得包装为通过。

## 2. 门禁等级

| 等级 | 名称 | 证明问题 | 通过后允许 |
| --- | --- | --- | --- |
| L0 | 文档与范围 | 人和 AI 是否执行同一产品 | 开始实现 |
| L1 | 静态与单元测试 | 代码契约是否一致 | 合并功能分支 |
| L2 | 构建与服务启动 | 制品和服务能否真实启动 | 进入集成测试 |
| L3 | API 与持久化 | 数据、状态、权限能否真实闭环 | 进入用户操作测试 |
| L4 | 浏览器/真机用户流 | 普通用户是否真的能完成 | 进入预生产 |
| L5 | 外部依赖与履约 | 支付、对象存储、印刷、物流是否真实 | 小规模试运营 |
| L6 | 业务与质量 | 产品是否值得扩大 | 扩大获客或进入 P1 |

## 3. L0：文档与范围门禁

执行：

```bash
node scripts/verify-xunjing-c-docs.mjs
npm run test:run -- scripts/project-structure-contract.test.mjs
```

必须满足：

- `docs/README.md` 可从根 README 到达。
- 产品、对象、技术、任务、验收五份 CURRENT 文档互相链接。
- 当前分支写 `main`，不再把旧 `product/city-companion-main` 当主线。
- 当前范围明确是完整 C 端；合作方功能不进入 P0。
- AI 任务书每项有唯一 ID、依赖、路径和完成定义。
- 业务对象、API、状态、支付和验收口径无冲突。

证据：`commands.log`、脚本输出和当前提交哈希。

## 6. L3：API、持久化与权限门禁

每个 API 任务至少验证：

1. 正常请求。
2. 参数错误。
3. 未登录或临时令牌失效。
4. 错误 `tenant-id`。
5. 横向越权。
6. 重复请求和幂等。
7. 服务重启后的状态恢复。
8. 删除后的读取和对象存储状态。

必须保存脱敏证据：

```text
api/request.json
api/response.json
api/database-before.txt
api/database-after.txt
api/object-manifest.json
```

不得保存真实 token、Cookie、手机号、地址或长期签名 URL。

## 7. L4：真实用户操作门禁

至少覆盖桌面 H5、390×844 手机视口和一台目标真机/微信开发者工具。每条场景保存步骤、截图或视频、接口日志和最终业务 ID。

### U1 行后直接做作品

```text
内容入口 -> 旅行结束做作品 -> 选择 100+ 真实照片
-> 中断并恢复上传 -> 核对不超过 3 个问题
-> 实际旅程 -> 整本节奏 -> 完整旅行书首版 -> 翻页 -> 换一个安全版式 -> 一句修改 -> 回退版本
```

### U2 行前计划

```text
规划新旅行 -> 粘贴真实攻略链接
-> 获取失败时改正文/截图 -> 保存路线 -> 修改顺序
-> 动态预演 -> 手机分享 -> 同行查看
```

### U3 轻行中

```text
今日行程 -> 查看下一站 -> 调起第三方导航 -> 返回寻境
-> 记下这里 -> 拒绝持续定位 -> 行后仍生成作品
```

### U4 同行共同素材

```text
OWNER 邀请 -> VIEWER 只看 -> MEMBER 加入
-> 两人分别上传 -> 查看贡献者 -> MEMBER 删除自己的素材
-> OWNER 生成作品
```

### U5 订单与售后

```text
完整保护性首版 -> 一次付款 -> 确认校样
-> 印刷 -> 发货 -> 签收 -> 发起退款或重印案例
```

### U6 隐私与删除

```text
未授权用户访问失败 -> 分享页隐藏精确位置
-> 删除 Trip -> 原图/代理图/预览/PDF/视频进入删除任务
-> 再次访问失败
```

### U7 完整旅程回放与路线证据

```text
打开实际旅程 -> 播放 -> 暂停 -> 拖动到第二天
-> 点击地图照片标记 -> 展开同一时刻 -> 返回继续播放
-> 核对实轨实线/照片点线/交通虚线/未知断点
-> 回放结束 -> 分享回忆电影或继续翻阅旅行书
```

至少使用一趟有有效轨迹和一趟完全无轨迹的真实样本。无轨迹样本不得出现道路级连续实线；地图不可用时必须回退到按日时刻和媒体回放。

## 8. L5：外部依赖与真实履约门禁

### 8.1 对象存储

- 原图和制品不依赖单机目录。
- 100–250 张样本上传、下载、删除和跨实例访问成功。
- 签名 URL 短期有效，过期后失败。

### 8.2 地图和 POI

- 使用合法服务和商业授权范围内接口。
- 计划路线和实际路线标识不同。
- 印刷页地图来源、审图号和敏感地点检查通过。

### 8.3 支付

- 商户、回调域名、验签密钥和退款权限来自未提交环境配置。
- 至少一笔真实小额或正式订单完成支付回调核对；只有沙箱时必须标记预生产，不得写“真实付款完成”。

### 8.4 印刷与物流

- 锁定一个供应商、一个 SKU、文件规范、成本、时效、退款和重印责任。
- 至少 5 本真实样书或试运营订单完成生产，至少 1 本完成物流签收。
- PDF 页数、尺寸、出血、DPI、字体和订单信息可追溯。

## 9. L6：业务与质量门禁

第一轮以 30–50 名有效旅行用户为样本；最终扩大判断使用产品文档第 16.4 节的 50 人口径。

必须统计：

- 小红书、抖音、视频号、自然访问分别带来的有效用户。
- 上传开始率、100 张以上上传完成率和恢复成功率。
- 首版生成成功率、平均生成时间和打开率。
- 0–1 次关键修改占比、两轮内定稿率。
- 全款订单、真实签收、退款和重印。
- 每单人工介入分钟、模型/存储/印刷/物流/支付/售后成本和贡献毛利。
- 预演生成、分享、同行打开和新旅程创建。
- 完整旅程回放打开、完成、按日/时刻跳转，以及回放后分享电影或翻阅旅行书。
- 地点组修正、地图降级、整本节奏打开、换版和需人工重排页面比例。
- 回忆电影分享、再次打开、加印和转介绍。

Go 条件：

- 50 个有效用户至少 10 个真实付费。
- 80% 标准订单无需运营逐页调整。
- 80% 两轮内定稿。
- 退款和重印低于 5%。
- 单本贡献毛利为正。
- 无高危隐私、支付、地图或内容合规问题。

No-Go 条件：

- 50 个有效用户少于 5 个付费订单。
- 超过 30% 标准订单需要人工逐页调整。
- 没有真实支付、印刷或签收证据却要求扩大投放。
- 任何高危数据泄露、越权、支付重复、错误印刷或无法删除问题未关闭。

每个任务目录必须有 `README.md`：

```markdown
# <TASK-ID> 验收证据

- 分支：
- 提交：
- 环境：
- 执行人/AI：
- 日期：
- 结论：PASS / PARTIAL / BLOCKED_ENV / FAIL

## 修改范围
## 命令与结果
## 用户操作路径
## API/数据库/对象存储证据
## 截图与制品
## 已知限制
## 下一任务依赖
```

最终发布证据包还必须记录：

- GitHub 和 Gitee 对应提交哈希。
- `HEAD...github/main` 与 `HEAD...origin/main` 的 `0 0` 结果。
- 构建制品 SHA-256。
- 环境变量名清单，但不含值。
- 当前未关闭 blocker 和明确 Go/No-Go。
